# 发票报销完整用户手册

> 文档版本：1.2
> 适用 App 版本：v0.2.6
> 更新日期：2026-09-19

## 关于本手册

本手册帮助你在 Mac 上安装《发票报销》，绑定 Gmail 或 QQ 邮箱，创建月份或自定义批次，并由 App 自动扫描、识别、安全筛选和导出报销材料包。

如果你只想尽快完成第一次报销，请先阅读《发票报销快速入门》。

### 最重要的工作原则

**默认流程在 App 内全自动完成。** 设置并启用邮箱后，创建批次时保留“创建后自动处理并导出”，然后等待完成摘要。只有异常计数不为 0 或结果与原件不符时，才需要进入待处理池人工修正并重跑。所有操作都在《发票报销》App 内完成，不需要 Codex、Agent 或其他外部自动化工具。

## 1. 开始之前

### 1.1 系统要求

| 项目 | 要求 |
|---|---|
| Mac 芯片 | Apple Silicon，即 M1、M2、M3、M4 或更新芯片 |
| macOS | macOS 11 或更高版本 |
| App 版本 | v0.2.6 |
| 安装包 | `invoice-reimbursement-0.2.6-macos-arm64.dmg` |
| 邮箱 | Gmail 或 QQ 邮箱 |

当前安装包不支持 Intel Mac。如果你不确定芯片类型，打开 macOS 左上角苹果菜单，选择“关于本机”查看“芯片”。

### 1.2 当前分享版的安全提醒

v0.2.6 是用于本地分享的 Apple Silicon macOS 安装包。App 采用 ad-hoc（临时）签名并启用了 Hardened Runtime，但未使用 Apple Developer ID 签名，也未经过 Apple 公证。macOS 第一次打开时可能会阻止运行。

- 只从你信任的分享者处获取安装包。
- 不要为了运行本 App 关闭 Gatekeeper 或 macOS 的整体安全保护。
- 分享者应同时提供校验文件 `invoice-reimbursement-0.2.6-macos-arm64.dmg.sha256`。

将 DMG 和校验文件放在同一目录。熟悉终端的用户可以进入该目录并执行：

~~~bash
shasum -a 256 -c invoice-reimbursement-0.2.6-macos-arm64.dmg.sha256
~~~

校验成功时，输出应包含 `invoice-reimbursement-0.2.6-macos-arm64.dmg: OK`。校验失败时不要安装，应重新从可信分享者处获取 DMG 和校验文件。

### 1.3 本地优先与数据边界

发票文件、识别结果、批次和导出包都在当前 Mac 上处理与保存。App 通过你配置的 IMAP 邮箱连接读取邮件内容，从附件或支持的 HTTPS 链接获取原件。邮箱应用专用密码或授权码只保存在 macOS 钥匙串中，不写入 App 数据库，也不应写入文档、截图或聊天记录。

## 2. 下载、安装与首次打开

### 2.1 安装 App

1. 从分享者处获取 DMG 文件。
2. 双击 DMG 打开安装镜像。
3. 将《发票报销》拖入“应用程序”文件夹。
4. 等待复制完成，然后退出 DMG。

### 2.2 处理“无法验证开发者”

优先使用这种方法：

1. 在 Finder 的“应用程序”中找到《发票报销》。
2. 右键点击 App，选择“打开”。
3. 在再次出现的提示中选择“打开”。

如果没有“打开”选项：

1. 打开“系统设置 -> 隐私与安全性”。
2. 向下滚动，找到与《发票报销》相关的阻止记录。
3. 点击“仍要打开”，完成 macOS 验证。

### 2.3 确认首次打开成功

成功打开后，左侧应看到“控制台”“待处理池”“报销批次”和“设置”四个入口。首次使用时，控制台的邮箱账号和票据数量可以为空。

## 4. 绑定 Gmail 或 QQ 邮箱

### 4.1 不要输入普通登录密码

Gmail 需要“应用专用密码”，QQ 邮箱需要“授权码”。它们是为第三方邮件客户端生成的单独凭据，不是日常登录密码。

在 App 内，Gmail 会显示“获取应用专用密码”，QQ 邮箱会显示“获取邮箱授权码”。这两个按钮会打开邮箱服务商的帮助页。

### 4.2 Gmail 设置

1. 打开“设置 -> 邮箱账号”。
2. 邮箱类型选择 Gmail。
3. 输入完整 Gmail 地址。
4. 点击“获取应用专用密码”，按 Google 帮助页启用所需账号安全设置并生成密码。
5. 将生成的应用专用密码输入 App。
6. 默认 IMAP 服务器应为 `imap.gmail.com`，端口为 `993`。一般不需要改动高级连接设置。
7. 确认“启用此账号”已开启，同步间隔位于 5-1440 分钟之间。
8. 点击“测试连接”。看到“连接成功”后，点击“保存账号”。

### 4.3 QQ 邮箱设置

1. 打开“设置 -> 邮箱账号”。
2. 邮箱类型选择 QQ 邮箱。
3. 输入完整 QQ 邮箱地址。
4. 点击“获取邮箱授权码”，按 QQ 邮箱帮助页开启所需服务并生成授权码。
5. 将授权码输入 App 的“应用专用密码”字段。
6. 默认 IMAP 服务器应为 `imap.qq.com`，端口为 `993`。
7. 确认账号已启用，点击“测试连接”。看到“连接成功”后，点击“保存账号”。

![邮箱类型、地址、应用专用密码、同步间隔和连接测试](assets/mailbox-setup.png)

### 4.4 修改已保存的账号

已保存账号的密码字段会显示“留空以保留钥匙串中的密码”。如果你只修改同步间隔，可以留空。如果更换了授权码，请输入新凭据，重新“测试连接”后再保存。

## 5. 让 App 开始处理发票

这是绑定邮箱后最关键的一章。你可以用三种方式将票据送入待处理池。

### 5.1 方式一：点击“立即同步”

1. 进入“控制台”。
2. 确认“邮箱同步”区域中显示已保存且已启用的账号。
3. 点击右上角“立即同步”。
4. 等待同步完成。App 会依次处理所有已启用的邮箱账号。
5. 查看“最近新增”“待确认”“识别失败”和“疑似重复”的数量变化。
6. 点击对应数字或打开“待处理池”开始检查。

“立即同步”只处理已启用账号。如果按钮不可用，请回到“设置”，确认账号已保存且“启用此账号”已开启。

### 5.2 方式二：后台自动同步

1. 打开“设置 -> 同步与存储”。
2. 开启“后台自动同步”。
3. 在邮箱账号中设置同步间隔，可选范围为 5-1440 分钟。
4. 点击“保存运行设置”。

关闭主窗口后，App 会隐藏到 macOS 菜单栏，而不是直接退出。只要没有从菜单栏选择“退出”，后台自动同步仍可继续运行。

![后台自动同步、本地数据目录和导出目录](assets/storage-settings.png)

<!-- pagebreak -->

### 5.3 方式三：手动导入

1. 打开“待处理池”。
2. 将票据文件拖到“拖入票据文件”区域，或点击“选择文件”。
3. 等待页面显示“已导入”。
4. 在表格中点击新文件开始检查。

每个文件最大 50 MB。当前可导入 PDF、JPG、JPEG、PNG、DOC、DOCX、XLS、XLSX 和 ZIP。为获得最稳定的预览与识别结果，优先使用清晰的 PDF、JPG 或 PNG。

![待处理池的手动导入、状态标签和票据列表](assets/inbox-import.png)

### 5.4 正文中的 HTTPS 发票原件链接

除了邮件附件，App 还会检查正文中的 HTTPS 链接：

- 符合安全规则并通过文件类型校验的 PDF、JPEG、PNG 或 ZIP 发票原件会自动下载，再进入与附件相同的识别和去重流程。
- 支持的诺诺短链接会先解析到真实 PDF，校验确为发票文件后再保存。
- 如果附件图片里印着发票二维码，App 会直接扫描二维码：指向 HTTPS 发票原件的二维码按与正文链接相同的安全规则下载、校验、去重后导入，因此只发来“一张二维码截图”的邮件也不会漏票。
- 邮件随附的 ZIP、7z 压缩包会自动解开并挑出其中的发票文件；压缩包带密码时，App 会先尝试邮件正文里出现的口令。解压层数、单个文件和总容量都有上限，超出上限时保留为可见异常，不会中断后续发票或邮箱。
- 加密压缩包、RAR 等本地无法解开的格式会明确列为异常并写明原因，请手动解压后导入。
- XML 配套链接和不直接指向发票原件的通用 `fp.nuonuo.com/#/` 首页会被忽略，不会作为发票原件导入。
- 网络波动等临时失败会作为异常项保持可见。恢复后，重新运行原批次，或新建覆盖邮件日期的批次即可重试，不会重复导入已成功下载的原件。“立即同步”不会回看同步游标之前的旧邮件。
- 需要登录或依赖脚本的门户若不受支持，会保留为可见异常，不会中断后续发票或邮箱。

并非支持所有发票门户，也不要把普通网页链接当作可直接下载的发票。所有处理都在《发票报销》App 内完成，不需要 Codex、Agent 或浏览器自动化工具。

### 5.5 同步后会发生什么

App 会将新票据保存到本地，计算文件摘要，尝试读取发票内容，并生成建议日期、月份、分类、金额、城市和开票销售方。同一邮件附件通常不会在每次同步时重复导入。ZIP 成功展开出 PDF 或图片后，只处理展开的发票，不再把 ZIP 容器当作第二张票据。

如果 PDF 附件、邮件链接下载件或 ZIP 内副本的发票号码、销售方税号、金额和城市全部一致，App 会保留第一条作为主记录，将后续记录标记为“疑似重复”。未处理的重复项不会被自动纳入批次或导出。

创建自动批次时，App 会按批次日期范围回扫所有已启用邮箱，而且按“邮件实际收到日期”归属邮箱来源的票据。这不会改变日常增量同步的进度。

例如，新建 2026 年 8 月批次时，纳入的是邮箱在 2026 年 8 月 1 日至 8 月 31 日收到的发票邮件；即使邮件里的发票开票日期是 7 月，也仍按 8 月批次处理。8 月开票但 9 月才收到的邮件，不会归入 8 月批次。手动上传的文件没有邮件接收日期，仍按其发票开票日期判断批次范围。

### 5.6 邮件台账：确认没有漏票

“邮件台账”按邮件逐封记录处理结果，用来回答“这封邮件的发票到底进来了没有”：

| 台账状态 | 含义 |
|---|---|
| 已提取 | 这封邮件里的发票都已导入 |
| 部分提取 | 只导入了其中一部分，展开可以看到成功和失败的明细 |
| 未提取 | 这封邮件被判断为发票邮件，但没有任何发票进入 |
| 无需处理 | 通知、账单等无关邮件，App 不会为它创建票据 |
| 需关注 | 需要你看一眼的邮件，等于“部分提取 + 未提取 + 标记失败” |

顶部标签会显示每类的数量，展开一行会列出这封邮件带来的票据，以及失败原因（链接下载失败、压缩包已加密、格式不支持等）。搜索框可以按主题或发件人查找。

在“运行设置”里可以控制“发票全部提取完成后标记邮件为已读”。开启后（默认开启），只有当一封邮件的发票全部导入成功时，App 才会在邮箱里把这封邮件标记为已读（`\Seen`）；仍有失败时保持未读，方便你在邮箱里继续排查。

## 6. 在待处理池检查发票

### 6.1 五种状态

![待处理池状态变化](assets/item-status-flow.png)

| 状态 | 含义 | 你要做什么 |
|---|---|---|
| 待识别 | App 正在读取文件或等待识别 | 稍后刷新或等待自动完成 |
| 待确认 | 已有识别结果，但尚未人工确认 | 打开票据，检查后“保存并确认” |
| 识别失败 | 文件无法正常读取或内容不足 | 检查原件，必要时更换清晰文件，再“重新识别” |
| 疑似重复 | App 发现了内容相似的票据 | 核对后选择“确认保留”或“删除重复” |
| 可纳入批次 | 票据已确认且没有未处理的重复风险 | 将它归入报销批次 |

“可纳入批次”只表示票据已确认。导出还要求每张票据都有可用的归一化 PDF：已确认但缺少归一化 PDF 的票据会在状态旁显示“缺归一化 PDF”，批次详情也会阻止导出并给出修复入口。

列表中的“邮件收到”列显示邮件到达邮箱的本地时间，精确到分钟，用来确认这张票属于哪一封邮件。

### 6.2 打开票据详情

点击票据列表中的文件名。右侧会打开“票据详情”，包含：

- 原件预览。
- “导出就绪检查”清单：原件、归一化 PDF、开票日期、金额、分类五项，一眼看出这张票还差什么才能导出。
- 自动识别值（含来源、邮件收到时间）。
- 可编辑的最终值。
- 批次归属。
- 重新识别和保存按钮。

如果这张票是系统判定失败的，顶部会用红色“失败原因”说明具体原因；系统原因不会占用你自己的“备注”字段。

![票据详情中的原件预览、自动识别值和最终值](assets/invoice-review.png)

### 6.3 逐项检查最终值

| 字段 | 检查重点 |
|---|---|
| 分类 | 从交通、餐饮、住宿、招待中选择正确类别 |
| 开票日期 | 必须与发票原件一致 |
| 建议月份 | 决定发票更适合进入哪个月度批次 |
| 金额 | 使用元为单位，最多两位小数 |
| 城市 | 核对开票销售方所在城市 |
| 主体 | 核对开具发票的商户或销售方名称 |
| 备注 | 填写特殊说明，可留空 |
| 事项标签 | 标记会议、差旅等事项，可留空 |
| 项目标签 | 标记内部项目，可留空 |

高置信且字段完整的票据会在自动批次中直接确认。只当完成摘要显示异常，或你发现结果不对时，再打开票据逐项检查，修正后点击“保存并确认”。如果金额或月份不符合要求，App 会在字段附近显示错误，修正后再保存。

### 6.4 使用筛选和搜索

待处理池支持按状态、建议月份、分类、来源和关键词筛选。如果你从控制台的“最近新增”进入，页面可能带有“最近 7 天”筛选。可以点击“清除最近 7 天筛选”查看更早票据。

## 7. 处理识别失败和疑似重复

### 7.1 识别失败

1. 点击“识别失败”标签。
2. 打开票据，查看红色“失败原因”，它说明具体是哪一步没成功。
3. 确认文件不是空文件，图片清晰且未损坏。
4. 点击“重新识别”。
5. 如果仍然失败，优先获取更清晰的 PDF 或图片，再手动导入。

常见失败原因和处理方式：

| 失败原因 | 处理方式 |
|---|---|
| 原件格式 `.docx`/`.xlsx` 等不支持自动识别 | 改用 PDF/JPG/PNG 原件重新导入，或人工填写日期金额后把票据移出待处理队列 |
| 文件损坏或不是有效的发票文件 | 重新导出原件，或换成清晰的扫描件 |
| 文件已加密 | 先解除密码再导入 |
| 文件过于复杂或超出处理上限 | 拆分或压缩超大 PDF 后重新导入 |

Word、Excel 和压缩包原件即使能存进来，也不会被当成可识别的发票：这类票据会明确显示原因，而不会伪装成“待确认”。识别失败的票据不能归入批次。

### 7.2 疑似重复

1. 点击“疑似重复”标签。
2. 对照发票号、日期、金额、公司和原件内容。
3. 如果两张确实是不同票据，点击“确认保留”。
4. 如果是重复文件，点击“删除重复”。

删除会移除该重复项。操作前请先确认已有一份正确票据被保留。未处理的疑似重复票据不能归入批次。

## 8. 创建和管理报销批次

### 8.1 创建批次

1. 打开“报销批次”。
2. 点击“新建批次”。
3. 按自然月报销时选择“按月”，设置年份和月份。
4. 需要跨月或指定精确日期时选择“自定义范围”，设置开始日期和结束日期。
5. 保留默认勾选的“创建后自动处理并导出”。
6. 点击“创建并自动处理”。

![按月或自定义范围创建报销批次](assets/batch-create.png)

按月批次的月份对应邮箱收件月份，而不是发票票面上的开票月份。比如创建 8 月批次后，App 会扫描 8 月收到的邮件，并自动处理其中的发票。

### 8.2 等待自动处理完成

App 会显示“正在自动处理”，并依次执行指定日期范围的邮箱扫描、识别、安全审核、批次归属和报销包导出。不要在处理中退出 App。

完成后，页面显示“自动处理完成”和下列摘要：

- 新导入票据数。
- 已自动纳入票据数。
- 异常项数。
- 失败邮箱数。
- 有可导出票据时的导出目录，或“没有可导出的票据”提示。

如果所有已启用邮箱都同步失败，且批次仍没有已纳入票据，页面不会显示完成摘要，而会显示“自动处理未完成”和“所有已启用邮箱同步失败，请检查网络和邮箱授权后重试”。恢复网络或邮箱授权后，点击“重试自动处理”。

异常项为 0 且归属、张数和金额正确时，点击“在文件夹中显示”打开导出目录即可。

### 8.3 安全排除和人工修正

自动处理不会默认接受不确定的票据。疑似重复、OCR 识别不完整、文件损坏或读取异常、以及已归属其他批次的票据，都会被排除，不会悄悄纳入或导出。邮箱票据的批次月份按邮件收到日期判断，手动上传票据按发票开票日期判断。

只在异常项大于 0，或张数、金额、分类等结果不对时，才执行人工处理：

1. 进入“待处理池”，打开对应票据。
2. 处理疑似重复，或修正日期、月份、分类、金额等字段。
3. 点击“保存并确认”。文件异常时，换用清晰、完整的原件重新导入。
4. 回到批次详情，点击“再次自动处理”。

### 8.4 手动调整与导出

需要特殊调整时，仍可使用“加入推荐票据”，或在“调整票据”中选择票据后点击“归属所选票据”。日期超出批次范围、识别失败和未处理疑似重复的票据不可归入。

在批次详情顶部检查：

- 票据张数是否正确。
- 合计金额是否与预期一致。
- 交通、餐饮、住宿和招待分类汇总是否正确。
- “待确认”是否为 0。

批次中只要存在未确认票据，App 就会阻止导出。回到待处理池打开该票据，完成“保存并确认”后再导出。

批次详情还会列出其他阻止导出的票据（缺少归一化 PDF、原件缺失或无法读取等），并给出逐张处理入口：可以点击“补齐归一化 PDF”重新生成，或点击“移出批次”。自动处理与“再次自动处理”在导出前会先尝试补齐可修复的归一化 PDF，并把结果计入完成摘要的“补齐归一化 PDF”一项。

### 8.5 批量确认与批量删除

批次详情支持一次处理多张票据：

1. 勾选票据左侧的复选框，表头复选框可以全选当前列表。
2. 点击“确认所选票据”：把这批票据当前的识别值直接写成最终值并确认，随后立刻重新检查还有没有阻止导出的票据。
3. 点击“移出所选票据”：只把票据移出当前批次，票据仍留在待处理池，不会删除任何文件。
4. “清空待确认（N）”会把批次里所有待确认票据一次性确认，完成后显示逐张结果（成功、跳过，以及跳过原因）。

批量确认不会替你编造缺失的字段：日期、金额或分类不完整的票据会被跳过，并在结果里写明原因（格式不支持、日期超出批次范围等），不会静默通过。

“移出所选票据”不是删除。要真正删除票据，请到“待处理池”打开该票据，使用票据自己的删除入口。

### 8.6 编辑批次范围

需要调整批次覆盖的时间范围时，在批次详情点击“编辑批次范围”，修改开始和结束日期后保存：

- 范围最长 366 天，结束日期不能早于开始日期，日期格式错误会被拒绝。
- 保存后批次回到“草稿”状态并重新计算推荐票据；已纳入的票据不会被自动移出，需要时用“调整票据”手动处理。
- 日期范围之外但仍要报销的票据，请移到覆盖其日期的批次，或直接调整批次范围。

## 9. 导出报销材料

### 9.1 导出步骤

默认情况下，自动批次会直接生成报销包，完成摘要中会显示导出目录。点击“在文件夹中显示”即可打开。

如果取消了“创建后自动处理并导出”，或需要手动重新导出：

1. 打开已整理完成的批次。
2. 确认待确认为 0。
3. 点击“导出报销包”。
4. 等待页面显示“报销包已生成”。
5. 点击“在文件夹中显示”打开导出目录。

![导出成功后显示报销包的四个文件](assets/batch-export.png)

### 9.2 导出包内容

| 文件 | 用途 |
|---|---|
| `merged.pdf` | 将批次内发票整理为一份合并 PDF |
| `reimbursement.xlsx` | 报销明细表，包含发票字段和分类信息 |
| `originals.zip` | 批次中的原始票据文件归档 |
| `manifest.json` | 导出清单、文件信息和校验用元数据 |

一般分享给财务人员时，优先提供 `merged.pdf` 和 `reimbursement.xlsx`；需要原件核验或归档时，再提供 `originals.zip` 和 `manifest.json`。

### 9.3 更改导出目录

1. 打开“设置 -> 同步与存储”。
2. 在“之后的导出目录”旁点击“选择导出目录”。
3. 选择一个当前用户可写入的本地文件夹。
4. 点击“保存运行设置”。

目录变更只影响之后创建的报销包，不会自动移动已导出的包。如果选择了外接硬盘，导出时必须确保该硬盘已连接且可写。

## 10. 后台运行、数据目录与备份

### 10.1 关闭主窗口不等于退出

点击主窗口左上角的关闭按钮时，App 会隐藏窗口并继续保留在 macOS 菜单栏。菜单栏菜单提供：

- “显示发票报销”：重新打开主窗口。
- “立即同步全部”：同步所有已启用账号。
- “退出”：完全关闭 App。

当开启后台自动同步时，不要在希望 App 继续抓取邮件时选择“退出”。

### 10.2 本地数据目录

App 主数据目录为：

`~/Library/Application Support/com.invoice-desk.desktop/`

这个目录中包含数据库、票据原件、处理后文件和运行状态。正常使用中不要手动删除或重命名其中的文件。

### 10.3 导出诊断包

遇到同步、识别或导出问题时，在「运行设置」里点击「导出诊断包」。App 会在导出目录写一个
`invoice-diagnostics-<时间戳>.zip`，包含三个文件：

| 文件 | 内容 |
|---|---|
| `summary.txt` | 可读概览：版本、数据库计数、迁移版本、账号配置、最近同步记录、邮件台账摘要、存储目录与一致性统计 |
| `report.json` | 同一份数据的结构化版本，便于比对或附加到问题报告 |
| `README.txt` | 说明这个包包含什么、不包含什么 |

诊断包**不包含**邮箱授权码或应用专用密码、发票原件与归一化 PDF 的正文、导出报销包内容；邮箱地址已打码（形如 `z***@qq.com`），涉及密码的日志行整行省略。把 `summary.txt` 发出去即可，不需要附带发票文件。

### 10.4 备份

1. 从 macOS 菜单栏的 App 菜单选择“退出”。
2. 在 Finder 中选择“前往 -> 前往文件夹”。
3. 输入 `~/Library/Application Support/`。
4. 将整个 `com.invoice-desk.desktop` 文件夹复制到安全的备份位置。
5. 同时备份你设置的外部导出目录。

邮箱应用专用密码或授权码只保存在 macOS 钥匙串中，不会因为复制数据目录而自动备份。迁移到另一台 Mac 后可能需要重新输入授权码。

### 10.5 卸载

将 App 从“应用程序”移到废纸篓不会自动删除本地数据目录、导出包或 macOS 凭据存储中的凭据。需要完全清理时，请先备份必要资料，再由熟悉 macOS 数据管理的人员处理。

## 11. 常见问题

### 11.1 macOS 阻止首次打开

**检查：** 确认安装包来自信任的分享者，并核对版本和 SHA-256。
**处理：** 在 Finder 中右键点击 App 后选择“打开”，或在“系统设置 -> 隐私与安全性”中选择“仍要打开”。不要全局关闭 Gatekeeper。

### 11.2 邮箱“测试连接”失败

**检查：** 邮箱类型、完整邮箱地址、应用专用密码或授权码、IMAP 地址和端口。
**处理：** 重新生成授权码并输入。Gmail 默认使用 `imap.gmail.com:993`，QQ 默认使用 `imap.qq.com:993`。确认网络可用后再次测试。

### 11.3 点击“立即同步”后没有发票

**检查：** 账号是否已启用，邮件是否包含受支持的附件或可直接获取的 HTTPS 发票原件链接，以及原件是否以前已同步。正文中的 XML 配套链接和通用 `fp.nuonuo.com/#/` 首页不会作为原件导入。
**处理：** 打开“待处理池 -> 全部”，清除月份、分类、来源、搜索和“最近 7 天”筛选，并检查可见异常。如果旧邮件中的链接临时失败，恢复网络后，重新运行原批次，或新建覆盖邮件日期的批次；“立即同步”不会重新读取已越过同步游标的旧邮件。仍不受支持时，从可信来源取得原件后手动导入。

### 11.4 原件识别失败

**检查：** 文件是否为空，图片是否清晰，PDF 是否能正常打开，文件是否超过 50 MB。
**处理：** 打开票据后点击“重新识别”。仍失败时，使用更清晰的 PDF、JPG 或 PNG 重新导入。ZIP、Word、Excel 等原件无法生成归一化 PDF，App 会提示格式不支持，并保留你已填写的内容；这类原件需要改用 PDF、JPG 或 PNG 重新导入。

### 11.5 发票被标记为“疑似重复”

**检查：** 发票号、日期、金额、公司和原件是否真的相同。
**处理：** 不同票据选择“确认保留”；重复文件选择“删除重复”。

### 11.6 发票无法归入批次

**检查：** 票据是否为“可纳入批次”，是否存在识别失败或疑似重复，日期是否与批次范围冲突。
**处理：** 先在待处理池完成确认或重复处理，再从“调整票据”重新选择。

### 11.7 自动处理显示“没有可导出的票据”

**检查：** 邮件日期是否在批次范围内，完成摘要的异常项是否大于 0，待处理池中是否有疑似重复、OCR 不完整或文件异常。
**处理：** 这不会生成空报销包，也不会丢失已导入票据。确认日期范围和邮箱后，处理异常票据，再回到批次点击“再次自动处理”。

### 11.8 所有邮箱都处理失败

**检查：** 网络、邮箱是否仍启用、授权码是否过期，以及“测试连接”是否成功。
**处理：** 页面会显示“自动处理未完成”和“所有已启用邮箱同步失败，请检查网络和邮箱授权后重试”，不会继续归属票据、导出可能不完整的报销包或把失败显示为完成。已抓取的部分数据仍保留在待处理池。恢复网络或更新授权码，在设置中重新测试并保存邮箱，然后回到原批次点击“重试自动处理”。

### 11.9 导出目录不可用或导出失败

**检查：** 目录是否存在且可写，外接硬盘是否已连接，是否有足够可用空间。
**处理：** 已安全纳入的票据仍保留在批次中。恢复原导出路径或外接盘，再打开设置查看存储状态。如果显示“导出恢复失败”，在原路径恢复后点击“重试导出恢复”；否则回到批次重试导出或再次自动处理。不要手动删除未完成导出的临时文件。

### 11.10 “导出报销包”被阻止

**检查：** 批次顶部的“待确认”数量是否大于 0，以及批次详情是否列出阻止导出的票据。
**处理：** 待确认数量大于 0 时，回到待处理池打开未确认票据，检查并点击“保存并确认”。批次详情列出缺少归一化 PDF 或原件异常的票据时，点击该行的“补齐归一化 PDF”；无法补齐的（ZIP、Word、Excel 原件）点击“移出批次”，改用 PDF、JPG 或 PNG 重新导入。两项都清空后即可导出。

### 11.11 发票全部导入了，邮件在邮箱里还是未读

先看“运行设置”里的“发票全部提取完成后标记邮件为已读”是否开启。即使开启，也只有当一封邮件的发票全部导入成功时才会标记已读；仍有失败时故意保持未读，方便你在邮箱里继续排查。若邮箱服务商不支持通过 IMAP 标记已读，台账里会显示原因，此时请在邮箱网页端手动处理。

### 11.12 同步一直提示“读取邮箱凭据超时”

这说明 App 读不到钥匙串里的邮箱凭据。macOS 只在**由 App 自己创建**该钥匙串条目时才给出完整授权；若条目是其他程序写入的（重装、重新签名或手工修复过之后可能如此），App 每次读取都会等一个授权弹窗，20 秒后超时，并把该账号标记为暂停自动同步。

处理方式：

1. 打开「运行设置 → 邮箱账号」，在「应用专用密码」里重新粘贴一次授权码，点「测试连接」，显示「连接成功」后再点「保存账号」。App 会重建条目，之后的读取不再需要确认。
2. 保存成功后点一次「立即同步」，清除“暂停自动同步”状态。
3. 授权码在 QQ 邮箱「设置 → 账户 → POP3/IMAP/SMTP 服务」获取；忘了可以重新生成一个。

### 11.13 邮件里明明有发票，台账却显示“未提取”

展开这封邮件的台账行，看失败原因：

- 提示链接下载失败：打开邮件里的链接手动下载 PDF，再从“待处理池”拖入导入。
- 提示压缩包已加密：先用密码解压，再导入解压出的 PDF。
- 提示格式不支持：把原件另存为 PDF/JPG/PNG 后重新导入。
- 没有失败提示但也没有票据：这封邮件可能被判为“无需处理”（例如通知或对账单）。确认是发票邮件时，请把原件手动导入。

### 11.14 关闭窗口后找不到 App

**检查：** macOS 菜单栏中是否还有《发票报销》图标。
**处理：** 点击菜单栏图标，选择“显示发票报销”。如果图标也不存在，从“应用程序”重新打开 App。
