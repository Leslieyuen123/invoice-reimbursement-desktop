# 批次全自动处理设计规格

日期：2026-07-22
状态：用户已授权按推荐方案直接实施
目标版本：发票报销 v0.2.0

## 1. 目标

普通用户只需要在 macOS 桌面 App 中选择月份或自定义日期范围并创建批次。App 随后自动完成该范围内的邮箱扫描、票据提取、本地识别、安全审核、批次归属和报销包导出，不依赖 Codex、外部 Agent 或逐张人工确认。

自动化完成后，用户直接看到导出目录、已纳入票据数、总金额和异常项数量。用户仅在最终成果不符合预期时进入待处理池查看异常或修正票据。

## 2. 成功标准

1. 创建 2026 年 5 月批次时，App 使用 IMAP 查询 `2026-05-01`（含）至 `2026-06-01`（不含）的邮件，不受日常增量同步游标影响。
2. 每个已启用邮箱都参与批次扫描；未启用账号不参与。
3. 邮件附件和支持的下载链接继续沿用现有导入、原件保存、OCR、去重和安全限制。
4. 日期、金额、分类和标准化 PDF 齐全、识别无警告、且无重复嫌疑的票据自动确认并归入批次。
5. 识别失败、字段不完整、OCR 有警告、疑似重复或缺少标准化 PDF 的票据不被强行纳入，统一计入异常结果。
6. 至少存在一张可安全纳入的票据时，App 自动生成 `merged.pdf`、`reimbursement.xlsx`、`originals.zip` 和 `manifest.json`。
7. 没有可导出票据、所有邮箱失败或导出失败时，App 保留已抓取数据并显示可恢复的结果，不伪造成功状态。
8. 重复执行同一批次不会重复保存相同邮件 part，也不会重复归属同一票据。

## 3. 方案比较

### 3.1 前端串联现有命令

前端依次创建批次、同步账号、查询候选、确认、归属和导出。改动较少，但窗口刷新、组件卸载或中途失败容易留下不可解释的半成品，且业务规则散落在 React 页面中。

### 3.2 后端单一编排服务（采用）

新增批次自动化服务和一个 Tauri 命令。前端只发起一次请求并显示结果；Rust 服务负责整个顺序、错误隔离和结果汇总。该方案复用现有服务，业务边界清楚，能够在没有 Agent 的环境中独立运行，也便于端到端测试。

### 3.3 持久化任务队列

为每个阶段建立数据库任务、崩溃恢复和断点续跑。可靠性最高，但会显著增加状态机、迁移和恢复界面，不是当前单机版本证明核心流程所必需的复杂度。本版本不采用；现有的同步去重和导出事务仍保证重试安全。

## 4. 用户流程

### 4.1 创建批次

“新建批次”页面保留按月和自定义范围两种模式，并新增默认开启的“创建后自动处理并导出”开关。

用户点击主按钮后：

1. App 创建批次。
2. 自动进入批次详情页。
3. 页面显示“正在扫描邮箱并处理票据”，禁用重复启动按钮。
4. 后端依次处理所有已启用邮箱。
5. App 自动纳入安全通过的票据并导出。
6. 页面显示完成摘要和导出目录。

关闭自动处理开关时，仍按原行为只创建空批次，满足手动整理场景。

### 4.2 已有批次

批次详情页新增“一键自动处理”按钮。用户可对未自动处理、处理失败或日期调整后的批次重新运行。重跑继续使用邮件来源唯一键、文件哈希和批次归属规则去重。

### 4.3 完成结果

成功摘要显示：

- 扫描邮箱数和失败邮箱数。
- 新导入票据数。
- 自动纳入票据数。
- 异常票据数。
- 导出票据数、总金额和导出目录。

存在异常时使用中性警示，不把整次任务标记为失败。用户可以点击“查看异常项”进入带状态筛选的待处理池。

## 5. 日期与邮箱同步规则

### 5.1 两类同步

日常同步和批次扫描是不同语义：

- 日常同步继续使用持久化 UID 游标，只抓取游标后的新邮件；移除原先固定的 2026 年 6–7 月日期限制。
- 批次扫描使用批次 `start_date` 和 `end_date + 1 天` 生成 IMAP `SINCE` / `BEFORE` 条件，并使用仅在本次调用中存在的临时 UID 游标分页。它不读取或覆盖日常同步游标。

这样即使日常游标已经走到 7 月末，新建 5 月批次仍能完整回扫 5 月。

### 5.2 范围含义

邮箱查询按服务器 IMAP `INTERNALDATE` 执行，开始日期包含、结束日期包含。结束日期传给 IMAP 时转换为下一日的 `BEFORE` 日期。

自定义范围最多允许 366 天自动扫描，避免误选多年范围导致不可控下载。原有批次本身仍可保存更长范围，但一键自动处理会返回明确的日期范围校验错误。

### 5.3 分页与限制

每次 IMAP 读取继续遵守现有的单封邮件、单批总字节数、单次消息数、附件数、ZIP 条目数和解压字节数限制。范围扫描循环获取后续 UID 页，直到临时游标不再前进。超过限制的单封邮件继续生成可见的失败项，其余邮件继续处理。

## 6. 自动审核规则

### 6.1 自动通过

票据必须同时满足以下条件：

1. `recognition_status = succeeded`。
2. OCR/提取没有警告，因此识别服务已将其标记为自动确认。
3. `dedupe_status` 不是 `suspected_duplicate`。
4. 发票日期在批次日期范围内。
5. 金额存在且为合法人民币分值。
6. 自动分类存在；自动确认时将建议分类复制为最终分类。
7. 建议归属月份存在。
8. 原件和标准化 PDF 都存在于 App 管理目录中。
9. 当前没有归属其他批次。

通过后，票据变为“可纳入批次”，随后批量归入当前批次。

### 6.2 异常隔离

以下情况保持在待处理池，不自动猜测或删除：

- 识别失败或仍待识别。
- 缺少日期、金额或分类。
- OCR 返回资源、版式或质量警告。
- 疑似重复。
- 发票日期不在当前批次范围。
- URL 占位文件尚未取得真实原件。
- 缺少标准化 PDF 或文件校验失败。
- 已归属其他批次。

异常不会被加入批次，因此不会阻断当前批次中正常票据的导出。疑似重复不会自动选择“保留”或“删除”，避免重复报销。

## 7. 后端结构

### 7.1 IMAP 查询模型

`infra::imap` 新增经过校验的日期范围类型，并为 `ImapGateway` 增加范围抓取能力。生产网关共用同一个底层抓取函数：日常模式只带 UID 条件，范围模式同时带 UID、`SINCE` 和 `BEFORE`。

### 7.2 同步服务

`SyncService::run_range(account_id, start_date, end_date)`：

- 读取账号和钥匙串凭据。
- 使用临时游标循环抓取整个范围。
- 复用现有邮件解析、导入、附件展开和识别逻辑。
- 记录同步运行结果和账号错误，但不修改日常 `sync_cursors`。

### 7.3 自动化服务

新增 `BatchAutomationService`，依赖邮箱仓库、范围同步、批次、票据和导出服务。服务按以下顺序执行：

1. 读取并校验批次。
2. 列出已启用账号并逐个范围同步，收集账号级失败。
3. 分页读取日期范围内未归属候选。
4. 自动确认具备完整可信字段的票据，并设置最终分类。
5. 批量归属所有可导出票据。
6. 对非空批次调用现有事务化导出服务。
7. 返回结构化结果。

同一批次同时只能运行一个自动化任务；并发点击返回冲突。账号操作继续复用现有每账号锁，避免与设置保存、日常同步并发。

### 7.4 命令和 DTO

新增 `run_batch_automation(batchId)` 命令及 `BatchAutomationResultDto`。DTO 只暴露用户需要的计数、失败账号的脱敏错误、导出结果和异常数量，不暴露邮箱授权码、邮件正文或本地内部路径之外的敏感诊断。

## 8. 错误与恢复

- 单个邮箱连接失败且至少另一个邮箱完成：继续处理成功邮箱，结果中记录失败账号；若已有可导出票据，仍完成导出。
- 所有邮箱失败：在票据归属和导出前返回失败结果，保留已导入的部分进度和每个账号的可操作错误，重试成功后再生成完整报销包。
- OCR 或单张附件失败：保留异常项，继续后续邮件。
- 数据库、文件系统或导出事务失败：命令返回错误，现有同步导入和导出恢复机制负责保持数据一致；用户可在批次详情页重试。
- 用户重复运行：邮件 part 唯一索引和文件哈希去重保证不重复导入；已经属于当前批次的票据不重复操作。
- App 退出：现有 tracked operation 和优雅关闭逻辑等待自动化命令内的同步与导出收口，超时后沿用既有恢复策略。

## 9. 测试策略

### 9.1 Rust 单元与集成测试

- IMAP 日常查询不再带固定月份，范围查询正确生成跨月、闰月和年末日期。
- 范围扫描忽略日常持久游标且不覆盖它。
- 大于一页的范围结果完整处理且不死循环。
- 识别完整时最终分类与自动确认同时落库；有警告或缺字段时保持待确认。
- 自动化服务只归属安全票据，隔离失败、重复、范围外和缺 PDF 项。
- 单邮箱失败不阻断其他邮箱和已有正常票据导出。
- 重跑不会重复导入、重复归属或覆盖其他批次。
- 命令 DTO、命令白名单和 AppState 依赖装配通过测试。

### 9.2 React 测试

- 创建页默认开启自动处理，创建成功后调用新命令并导航到详情。
- 用户关闭开关时只创建批次。
- 运行期间按钮禁用并显示稳定进度状态。
- 完成摘要准确显示导出、异常和邮箱失败信息。
- 失败后保留批次并提供重试，不返回创建表单。

### 9.3 完整验证

- `npm test`、`npm run lint`、`npm run build`。
- `cargo fmt --check`、`cargo clippy --all-targets --all-features -- -D warnings`、`cargo test`。
- Playwright 检查 800x700、1440x900 和 1728x1117 三种窗口尺寸，确认创建页、运行状态和结果摘要无重叠、截断或水平滚动。
- 使用测试邮箱或 IMAP 假实现完成“创建 5 月批次 -> 扫描 5 月 -> 自动归属 -> 自动导出”的端到端场景。
- 构建 Apple Silicon DMG 并检查 OCR sidecar、最低 macOS 版本和产物可启动性。

## 10. 安全边界

- 不引入云端 AI、第三方 Agent 或新的外部数据服务。
- 邮箱授权码继续只保存在 macOS 钥匙串。
- 自动审核不绕过重复检测、文件边界检查、金额校验或导出事务。
- 不自动删除邮件、邮箱附件或疑似重复票据。
- 不把原始邮件正文、授权信息或绝对内部文件路径写入前端错误和日志。

## 11. 本版本范围外

- 企业审批流、多人协作、云同步和跨设备任务。
- 自动修改邮箱邮件状态、标签或文件夹。
- 使用大语言模型判断发票真实性或税务合规性。
- 对识别不完整的票据进行无依据的字段猜测。
- 持久化任务队列和应用崩溃后的逐阶段断点续跑。
